## 2. 검색 방법론

`questions.json` 항목 스키마: `year` / `session` / `subject` / `q_no` / `text` /
`choices` / `answer` / `solution` / `difficulty` / `q_type` / `tag` / `steps` /
`quality` / `solution_svg`. key = `{year}_{session}_{q_no}`.

`tag`는 concept/category 필드로 v3.2 함정 항목과 다수 1:1 대응하나, **tag 버킷이
오염되어 있어**(Section 4 참조) tag만으로는 신뢰 불가하다. 따라서:

1. **text/choices 내용 키워드 검색을 1차 기준**으로 삼고
2. tag는 교차검증 라벨(TAG-OK / TAG-MISMATCH)로만 사용
3. 대표성 점수 = difficulty(4~5 가점) + q_type(개념형 가점) + 보기 함정형 어구
   ("틀린/옳은/아닌 것") + choices 4개 + OCR 잔류물 없음

검색은 read-only Python 스크립트 1회용(`/tmp/trap_map_search.py`, repo 외부)로 수행.

대표성 판정 기준: v3.2 항목의 "대표 보기 함정"을 실제 choices에서 검증 가능한가,
text/choices가 OCR-clean한가, 함정 유형이 항목 본질과 정합하는가.

데이터 리스크 라벨: `source-clean` / `needs-cleanup`(OCR 일부 손상, 정정 필요) /
`hold-source`(대표 문항 부재 또는 출처 확인 불가) / `statute-risk`(법규 개정으로
구 출제 기준 무효) / `DQ-risk`(tag/subject 오라벨, 중복 등 데이터 품질 이슈).

pedagogy apply 적합성: `high`(clean + 함정 명확 + 보기 검증 가능) /
`medium`(부분 손상 또는 함정-항목 정합 약함) / `low`(후보 부재 또는 statute/DQ 차단).
