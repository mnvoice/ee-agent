## 2. 트랙 A — 정답키 추출 버그 (ee-agent 본 트랙)

### 2.1 진단 — patterns A/B/C 구분

**가설**: 정답키 1번 비율 33% (정상 25%) → "1번 fallback" 의심.

**3단계 CLI 위임 진단**:
- [1] 분포: 1=33% / 2=24% / 3=16% / 4=27% (N=100)
- [2] grep: `runner.py:243` `all_ans_one = all(q.correct_answer == 1 for q in questions)` — fallback은 *명시 분기 없음*. "추출 실패 = 미수정 = 초기값 1".
- [3] raw: 의심 7건 중 6건이 추출 누락 + 1건(Q65)은 정상 추출

**원인 정정 (1차 보고 자가 수정)**: 누락은 32건이 아니라 **11건 (Q1~Q11)**. 32건은 줄경계 앵커 시뮬레이션 결과였음. production 정규식은 89/100.

**근본 원인**: `runner.py:83` `start_page = max(0, len(pdf.pages) // 2)` 휴리스틱이 2026 1회 CBT PDF 레이아웃과 미스매치. 답키가 page 16-17, production 스캔은 page 18부터 → Q1~Q11 답키 통째로 누락.

**영향 범위**: 84개 PDF 중 production 추출 로직을 *통과하면서 누락*하는 PDF는 단 1개 (2026 1회 CBT). 다른 PDF는 production=0(별 답키 경로) 또는 100/100 정상.

### 2.2 Patch + 재채점

**Patch**: `_ANSWER_KEY_START_PAGE_OVERRIDE` 맵 추가. `"과년도2026년 1회 CBT 기출.pdf": 16`.

**11건 정정**: Q1=4, Q2=3, Q3=4, Q4=3, Q5=3, Q6=4, Q7=2, Q8=2, Q9=2, Q10=4, Q11=1.

**재채점 결과**:
- 진짜 점수: 84/100 → **89/100** (+5)
- 분포: 1=33% → **23%** (정상 분포 근접)
- 효과: 오답→정답 7건 (Q1, Q2, Q4, Q6, Q7, Q9, Q10), 정답→오답 2건 (Q3, Q5 — fallback=1과 solver pred=1 우연 일치한 가짜 정답)

**verify-agent 원칙 사례 보강**: Q3, Q5는 *결과는 맞았지만 과정이 맞은 게 아닌* 가짜 정답. "주장(맞음 표시) ≠ 증거(진짜 풀이)"의 깨끗한 사례.

### 2.3 D-등재 후보

## 3. 트랙 B — 풀이 도구 (MVP-2 종착점)

### 3.1 결정 사항

| 항목 | 결정 | 비고 |
|---|---|---|
| 모드 | 연습 (즉시 채점 + 노트) | 시험 모드는 후순위 |
| 그림 처리 | (γ) 페이지별 PNG | 매핑은 수동, 캐러셀 UI |
| 배포 | (γ) Artifact 먼저 → 흐름 확정 후 PWA | 흐름 확정에 가까워짐 |
| 메타 추출 | (a) law_used 재활용 | 비용 0, 새 LLM 호출 없음 |
| 학습 메모 입력 | 펜 캔버스 1개 (자유) | Apple Pencil 압력 감지, 좌표 저장 |

### 3.2 학습 메모 UI 진화

```
v0 (단일 textarea, 자유)
  ↓ 사용자 신호: "Q3, Q4 두 스타일 모두 필요"
v1 (이해/암기 두 textarea, AI 메모 + 사용자 메모)
  ↓ 사용자 신호: "펜 입력, 1박스, 라벨 삭제"
v2 (HandwritingCanvas 1개, 자유 작성)
```

v0→v1은 *콘텐츠 분류 욕구*(이해 vs 암기)에 응답. v1→v2는 *입력 방식 욕구*(펜)에 응답. 분류는 콘텐츠를 *읽을 때* 의미 있고, *쓸 때*는 자유가 자연스러움 — 그래서 라벨 삭제가 옳았음.

### 3.3 펜 입력 구현 디테일

- Pointer Events API — `pointerType === 'pen'`로 Apple Pencil, `'touch'`로 손가락, `'mouse'`로 마우스
- 압력 감지 — `e.pressure` (0~1) → 선폭 1.2~3.0px
- 좌표 데이터 저장 — `[[{x, y, p}, ...], ...]` JSON
- 문항당 별도 storage 키 — `ee_hw_v1:Q1`, `ee_hw_v1:Q2`, …
- 5MB/key 한도 분산 → 한 메모당 평균 16KB로 안전
- `touch-action: none` — 캔버스에서 스크롤 캡처 방지

**향후 OCR 가공 가능성**: 좌표 데이터 그대로 보관됨. Google Vision digital ink, Apple PencilKit + Vision, MyScript 등이 같은 좌표 시퀀스 형식 사용. PNG 변환 불필요.

## 6. 미해결 / 다음 결정

### 6.1 데이터 호스팅 — 결정 필요
GitHub raw / Gist / Vercel / Cloudflare R2 중. 사용자 친숙도와 ee-agent 깃허브 사용 경험 고려하면 GitHub raw 가장 빠름. 단 private repo면 raw URL이 토큰 노출 위험.

### 6.2 Q2~Q6 stem 누락 (5건) — ee-agent 측 별건
`agent_outputs[0]`에 stem 필드 없음. 풀이 도구는 PDF 이미지로 우회 (좌측 PNG 보고 풀이). vision_solver가 텍스트만 회수 후 영속화 안 함이 근본 원인.

### 6.3 다른 회차 데이터 — 미점검
다른 PDF 그룹(production=0)은 별 답키 경로. 풀이 도구가 다른 회차로 확장될 때 baseline 신뢰성 점검 필요.

### 6.4 PWA 이전 — 흐름 확정 후
Artifact는 채팅 단위 일시적. 영구 사용은 PWA. 단 `window.storage` → `localStorage` 변환 + 호스팅 셋업 필요.

### 6.5 향후: 필기 OCR (보류)
좌표 데이터 보존됨. 한국어 + 수식 인식 모델 선택 필요. MVP 검증 후 결정.

## 8. 메타 관찰

### 8.1 §1.5 자기 적용 실패 (1회)
§3.1 항목 1 진술 후 사용자 [No preference]를 "위임"으로 잘못 해석. "어떤 옵션도 선호 안 함 = 진행 안 함"이 옳은 해석. 사용자 차단으로 정정됨. 사례 6 패턴에 추가 후보: *세션 문구의 4개 항목 단위*가 (a) 출처가 아니라 (c) 추정으로 처리되어야 했음.

### 8.2 토큰 인지
세션 중 사용자가 사용량 스크린샷 공유 (27% 세션 + 11% 주간). 형식 충족이 토큰 단위로 비싸다는 척도 직접 관찰됨. 이후 답변 길이 절제 의식적으로 적용.

### 8.3 verify-agent 원칙의 자기 적용 사례
- Q3/Q5의 가짜 정답 발견 (fallback과 solver pred 우연 일치) — 결과 ≠ 과정의 직접 사례
- (a) 옵션 선택 — LLM 생성 텍스트(law_used)는 *주장*임을 풀이 도구 UI에 명시 ("⚠ AI 생성 텍스트 · 검증되지 않음 · 참고용")
- 펜 입력 좌표 데이터 보존 — 사용자 작성이 *증거*. 향후 OCR로 가공해도 원본 보존
